# 完成後の知見還元（harvest） — この案件向け

この案件で得た学びのうち、**テンプレ原本（poster_template）に戻す価値があるもの**を抽出して渡すための手順。
テンプレ側の受け取り・適用手順は、テンプレリポの `docs/BACKPORT.md` にある。

## いつ

ポスター/チラシの完成時、または大きな節目（レイアウト確定・入稿後など）。

## 何を作るか

`_backport-inbox-from-<案件名>.md` を1つ作り、テンプレ保守者に渡す（テンプレリポの `docs/` に置いてもらう）。
このファイルは「処理待ちの受け箱」であって正式な docs ではない。

## 仕分けの原則

- **汎用 → テンプレ反映候補**：他の案件でも効く工夫・バグ修正・ルール（例：印刷の落とし穴、変数設計、ツール改善）。
- **案件固有 → 持ち込まない**：ブランドカラーの具体値、この案件だけのアイコン選定・図版・実測サイズ表、特殊な紙面構造。
- 各項目に**出典 commit**（ハッシュ＋件名）を引用する。推測は「推測」と明示する。
- 数値や挙動は**実コード／実履歴で裏取り**してから書く（保守者が独立検証しやすいように）。

## 雛形

```markdown
# バックポート受け箱：<案件名> → poster_template

> 下流案件 <パス> の制作で得た、テンプレ原本に還元すべき候補。
> 派生元テンプレ: <docs/PROJECT_LOG.md の「派生元」commit を転記>
> 作成日: <YYYY-MM-DD>

## 0. 前提
この案件の性質（サイズ・用途・テンプレとの違い）を一段落で。

## 1. ツール（tools/）の差分
- 何を / テンプレ現状 / 出典commit / 反映先候補

## 2. 汎用知見（spec / docs へ昇格）
- 症状・原因・教訓 / 出典commit / 反映先候補（spec §… など）

## 3. 再利用できる設計パターン（“選択肢”として足す候補）
- パターン名 / 実装の要点 / 出典commit / 任意採用か

## 4. 持ち込まない（案件固有）
- 箇条書き（ブランド色・固有アイコン・固有図版・固有実測値・特殊構造 など）

## 5. スコープ判断が要る論点（保守者へ）
- テンプレの抽象度・仕様根幹に触れる判断はここに集約
```

完成したら保守者に渡す。以降の適用はテンプレ側 `docs/BACKPORT.md §③` に従って行われる。
